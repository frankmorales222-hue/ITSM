# Architecture

Northstar Desk uses a layered modular-monolith architecture appropriate for the first internally hosted release.

## Runtime

- React and TypeScript provide the responsive browser interface. A production build is served by FastAPI, so normal use requires one browser URL and no frontend development server.
- FastAPI exposes a REST API with secure cookie sessions and CSRF headers.
- SQLAlchemy provides parameterized persistence. Alembic owns schema versioning.
- SQLite enables immediate single-machine evaluation. PostgreSQL is the supported production-style multi-user database through `ITSM_DATABASE_URL`.
- A separate Python worker polls IMAP, processes notifications, evaluates SLA state, and publishes health heartbeats.

The application is a modular monolith rather than distributed services because it is simpler to install and operate on one Windows host while retaining clear service boundaries. Authentication, email document storage, notification delivery, and identity sync are explicit extension points.

## Data model

Primary records are users, employees, teams, tickets, ticket messages, ticket history, assets, asset history, notifications, email messages, audit events, feedback, announcements, system state, and automation failures. Ticket numbers are generated by persistent per-prefix sequences and are never reused. Audit events have no update or delete API. Asset assignment history is append-only.

## Authorization

Role and record scope are both enforced server-side. End users are restricted to their own tickets and assigned assets. Technicians and leads are scoped to their team. Restricted tickets require assignment or manager/administrator authority. Auditors receive read-only normal-ticket, report, and audit access. UI navigation is convenience only; APIs remain authoritative.

## Future Entra ID integration

The session and authorization layer depends on an application user, not the password mechanism. Add an OIDC provider that validates Entra tokens, maps immutable Entra object IDs to local users, and invokes the same session creation function. Keep local accounts for break-glass administrators. Rollout should add tenant/issuer validation, group-to-role mappings, conditional access, claim normalization, account linking, and an audited migration process without changing ticket ownership foreign keys.

## External document storage

Attachment contents are deliberately never persisted. `EmailMessage.attachment_metadata` records name, MIME type, and size. A future document provider interface should return an opaque external reference after malware scanning and authorization checks; ticket records should store only that reference.
