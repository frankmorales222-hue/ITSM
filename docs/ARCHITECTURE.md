# Architecture

## Configurable service layer

Northstar Studio stores organization-owned form definitions as validated JSON field schemas. Ticket submissions retain both the form reference and a JSON snapshot of submitted values, so forms can evolve without changing historical records. Approval workflows resolve sequential steps to an active role or named user, while approval requests and append-only decisions preserve the operational history. Saved report definitions contain only whitelisted columns, filters, and grouping instructions; the server constructs authorized queries and never accepts report-authored SQL.

Approval email uses the existing notification outbox. The API records `pending_email` notifications transactionally with the approval decision, and the background worker delivers them through organization-configured SMTP credentials held in Windows Credential Manager. Failed delivery becomes a visible automation exception.

Northstar Desk uses a layered modular-monolith architecture appropriate for the first internally hosted release.

## Runtime

- React and TypeScript provide the responsive browser interface. A production build is served by FastAPI, so normal use requires one browser URL and no frontend development server.
- FastAPI exposes a REST API with secure cookie sessions and CSRF headers.
- SQLAlchemy provides parameterized persistence. Alembic owns schema versioning.
- SQLite enables immediate single-machine evaluation. PostgreSQL is the supported production-style multi-user database through `ITSM_DATABASE_URL`.
- A separate Python worker polls IMAP, processes notifications, evaluates SLA state, and publishes health heartbeats.

The application is a modular monolith rather than distributed services because it is simpler to install and operate on one Windows host while retaining clear service boundaries. Authentication, email document storage, notification delivery, and identity sync are explicit extension points.

## Data model

Organizations are the security boundary for users, employees, teams, tickets, assets, configuration, notifications, email events, audit events, announcements, feedback, and automation failures. Authenticated database sessions apply organization filters to every scoped query and stamp or reject writes at flush time. Primary records otherwise include ticket messages and history, asset history, and system state. Ticket numbers are generated by persistent per-prefix sequences and are never reused. Audit events have no update or delete API. Asset assignment history is append-only.

## Authorization

Organization, role, and record scope are enforced server-side. End users are restricted to their own tickets and assigned assets. Technicians and leads are scoped to their team. Restricted tickets require assignment or manager/administrator authority. Auditors receive read-only normal-ticket, report, and audit access. Foreign-record assignments are validated inside the current organization. UI navigation is convenience only; APIs remain authoritative.

## Organization integrations

Each organization owns its configuration and encrypted integration credentials. RingCentral operational settings and technician-extension mappings are editable by organization administrators. Credential values are encrypted before persistence and only presence/status is returned to the browser. The call-event connector remains disabled until credentials are supplied and an administrator enables it.

## Future Entra ID integration

The session and authorization layer depends on an application user, not the password mechanism. Add an OIDC provider that validates Entra tokens, maps immutable Entra object IDs to local users, and invokes the same session creation function. Keep local accounts for break-glass administrators. Rollout should add tenant/issuer validation, group-to-role mappings, conditional access, claim normalization, account linking, and an audited migration process without changing ticket ownership foreign keys.

## External document storage

Attachment contents are deliberately never persisted. `EmailMessage.attachment_metadata` records name, MIME type, and size. A future document provider interface should return an opaque external reference after malware scanning and authorization checks; ticket records should store only that reference.
